# Cocos Agent：Claude / Codex 与可视化编辑的产品总方案

2026-11-06 · 产品设计。M0 已按现有 MCP 接口实施，构建和验证边界见 [M0 实现记录](m0-editor-context-2026-11-06.md)；其他阶段仍为设计。面向产品、Orca、GitNexus 和 AI 接入开发。

**产品目标：一个工作台管理多个 Cocos 项目；人和 AI 在同一份 Prefab 上工作，AI 能看到修改后的真实画面，人能继续调整、保存和验收。**

下一步先交付“AI 知道我正在看什么”。随后接通“给美术稿 → 修改当前 Prefab → 自己看图和数值 → 修正 → 检查引用 → 交付”的 UI 闭环。保留现在中央编辑器、右侧真实终端的布局。

本文是后续工作的优先级入口。[API 标准](cocos-web-api-standard.md)和[方法目录](cocos-web-api-methods.md)保留为长期能力参考，不要求先完成整套平台。实例预算、独立浏览器 Play、全局安装及外部 MCP 配置均不阻塞第一批。

## 1. 第一批究竟交付什么

用户在右侧 Claude 或 Codex 里说：“看一下我选中的节点。”AI 应直接答出正确项目、Prefab、节点，展示或读取同一画面，并给出尺寸、位置和相关错误。整个过程不要求用户再提供项目路径、复制编辑器地址，或重新启动一套编辑器。

第一批只做下面五项，复用现有 MCP、WebSocket 和共享文档：

| 项目                | 用户获得什么                             | 最小实现与完成条件                                                                                                                   |
| ------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 1. 固定连接         | Claude、Codex 和中央编辑器连到同一个服务 | Orca 为会话配置内置 MCP 启动器的绝对路径和目标实例；首次连接、重连均核对项目、实例与工具版本。错误实例拒绝编辑，不另起服务掩盖失败。 |
| 2. 当前页面上下文   | AI 知道当前 Prefab 和选中节点            | 页面通过现有 WS 上报页面身份、文档、epoch/version、选择及视口；服务提供只读查询。多窗口按会话绑定的页面区分。                        |
| 3. 图加数值         | AI 实际获得图片、包围盒和少量错误        | 一个紧凑的“当前上下文”调用返回选中节点及顶层节点的真实世界包围盒、视口和 PNG；完整节点树和日志按需读取。                             |
| 4. 画面与版本一致   | AI 不会拿旧截图判断新修改                | 沿用现有截图通道，增加页面身份、文档 epoch、实际渲染版本和取景信息；截图、测量、上下文不一致就重取或报未就绪。                       |
| 5. 修改和保存有边界 | AI 修改能在中央看见，且不覆盖新改动      | 复用现有原子 batch，增加服务端版本前提；保存核对磁盘哈希；保留同步 Prefab 保护。冲突回读，不盲目重放。                               |

**第一批验收口令：**在一个已经打开的 Prefab 中选择节点，分别让 Claude、Codex 读取当前画面，调整一个已授权属性，再读取修改后的图和数值。用户不离开编辑器就能看到同一变化。尚未完成此验收前，不以“新增了多少个 API”报告进度。

这一批不新建通用 HTTP 平台、十二域权限中心、24 小时操作日志、上传服务或跨进程资源管理器；继续使用现有认证和项目范围校验。涉及的少数工具仍需明确输入、输出、错误和版本契约。

## 2. 从美术稿到可交付 UI

### 用户的一次任务

以当前 `wptg-client` 的 `mtt_game_list_item.prefab` 为例：用户给参考图，说“按这张图调整列表项，复用项目素材，保留原来的业务逻辑，把标题和费用字段绑定正确”。这是目标场景，不是本次已经执行的修改。

| 步骤     | 用户看到的体验                       | AI 的工作与退出条件                                                                                          |
| -------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| 读现场   | 右侧确认当前项目、Prefab 和选中节点  | 获取同一服务的上下文、基线截图、尺寸和已有改动；目标锁定到具体文档，不能只记住“当前文件”。                   |
| 看参考   | 图片附在当前 AI 会话中               | 确认模型真的收到图片；识别布局、字体、间距、素材和状态。参考稿尺寸不明时先用明确假设，影响结果的缺项再询问。 |
| 找复用   | AI 简述准备改哪些部分                | 读取目标子树、脚本字段、已有素材与相近 Prefab；形成局部修改清单。保留未要求修改的业务字段和引用。            |
| 做修改   | 中央编辑器显示修改                   | 以可撤销批次修改尺寸、位置、Widget/Layout、Label/Sprite 和引用；每批基于刚读到的版本。失败不留下半批修改。   |
| 自己看   | AI 展示发现的差异并继续修正          | 获取本轮实际 PNG、测量和新增错误；对照参考图逐项检查。仅有“操作成功”返回不能结束任务。                       |
| 检查绑定 | 终端给出修改前后的引用清单           | 回读节点/组件/资源引用和事件；验证类型、目标、数组顺序、脚本及 handler。业务触发验证另标结果。               |
| 交付     | 前后图、改动摘要、检查结论和待确认项 | 声明草稿/已保存状态及基线版本；保存后核对文件，并在同源版本上复看。用户可继续提要求、保存或撤销本次修改。    |

```mermaid
flowchart LR
    A[参考图与需求] --> B[同一页面的图和数值]
    B --> C[读取结构与素材]
    C --> D[局部修改及绑定]
    D --> E[真实渲染与回读]
    E --> F{满足要求?}
    F -->|尚有明确差异| D
    F -->|满足或存在外部阻塞| G[证据与交付]
```

### 参考图和上下文的产品规则

- 支持用户提供截图、设计图和现有资源文件；图片是任务参考，文字需求决定修改范围。设计图里的文字不直接作为工具执行指令。
- 先复用项目已有资源和组件。没有切图、字体或授权素材时列出缺项；占位素材可以辅助布局，但不能宣称达到美术最终效果。把整张设计图铺成背景不算完成可编辑 UI。
- 优先调整现有 Prefab；新建时优先从同项目合适模板实例化或复制。项目中的真实组件、引用和布局习惯，比让模型凭空生成大段 DSL 更可靠。
- 需要比例判断时，同时保留全图与目标区域裁剪，记录参考稿尺寸、预览尺寸和缩放关系。文字溢出、对齐、裁切看图；宽高、边距、世界包围盒看数值；不以一个像素相似度分数代替验收。
- 编辑器自由缩放的 Scene 画面用于理解当前现场；美术对比使用明确的取景和尺寸。若需改变用户视口，提供可恢复的取景操作，不暗中改变用户选中项。
- 自我修正默认最多 3 轮；这是原型的可调交互预算，不是质量保证。连续无改善或缺素材时交付差异和阻塞项，用户可以继续；不能为了“通过”降低原要求。

## 3. 当前上下文与同一服务

### 3.1 会话绑定

启动 AI 会话时，Orca 保存 `执行主机 + 规范项目根 + 编辑器实例/启动代际 + 页面 ID` 的绑定，提供给 MCP 适配器。终端目录只是辅助信息，不作为唯一身份。

MCP 启动使用当前安装包内的绝对路径，开发覆盖路径须显式登记。不能仅依赖 PATH 优先级。配置仅作用于该会话，保留已有用户 MCP，不全局覆盖 Claude/Codex 配置，也不要求用户先全局安装工具。两个客户端分别用各自支持的会话配置方式；具体启动参数在实现时核对安装版本，不在产品文档猜测参数。

连接回执至少给出工具版本/build、项目身份、instanceId/代际和可用编辑能力；敏感连接凭据留在宿主与适配器之间。缺工具、版本不支持或实例不一致时，显示原因并停止该编辑调用。升级后重新握手，不能静默换用旧全局二进制。外部独立 AI 接入仍是后续能力。

Orca 已有项目实例时，内置会话使用“只连接指定实例”路径。短时无响应应区分“忙/未知”和“已退出”，不能因为一次超时就删记录、创建第二个服务。真正退出时由 Orca 恢复实例，重新核对版本和草稿状态。无需先建设跨进程的总管理器。

### 3.2 页面如何告诉 AI“我正在看什么”

现有浏览器间 BroadcastChannel 保留；新增通过已有 WS 上报页面状态，供服务端和 MCP 查询。状态包括 `viewId、docId、epoch、version、selectionRevision、选中节点、viewport、renderedVersion、connected`。

第一期复用现有连接记录保存最近状态，切文档/选择/视口时更新，断连立即标失效；不需要持久事件平台。查询和截图必须发给绑定页面，不能随便找另一张显示同名 Prefab 的标签。

用户开始任务后，任务绑定的文档保持不变。人切到别的 Prefab 时，AI 提示“任务仍在原 Prefab”，不可自动把后续写入转到新文档；新任务重新读取当前上下文。多页面无法确定目标时明确列出候选。用户仍可自由切换项目。

### 3.3 一个紧凑的读取入口

拟新增 MCP 工具 **`editor_context`**；这是本方案的新提议，当前六个工具中没有它。它把已有文档快照、页面状态、截图与少量日志组合成一次读取。长期与方法目录中的 `ui.selection.inspect`、`scene.measure`、`capture.take`、`logs.read` 对应，无需先实现这些独立公共端点。

| 输入/输出 | 最小契约                                                                                                                                   |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 输入      | 会话绑定的实例/page；可选 expectedDocument/epoch/version、是否要图片、日志游标。无绑定时拒绝猜测。                                         |
| 身份      | project、instanceId/代际、viewId、docId/path、epoch/version、工具版本。                                                                    |
| 选择      | 选中节点的句柄、名称、层级路径、组件摘要；无选择返回空，不替用户选中。                                                                     |
| 布局      | 选中节点与顶层节点的真实世界 AABB、坐标系/单位、激活与可见状态；同时返回视口、相机/缩放、像素尺寸、DPR。大场景显式截断并提供继续读取入口。 |
| 图像      | 独立 PNG image 内容，以及实际 renderedVersion、frame 标识和尺寸；图片不得塞进文本 Base64。                                                 |
| 诊断      | 默认最新 5 条相关错误；重复错误合并计数，附 total/truncated 与继续读取位置；保留编译失败总状态。                                           |
| 就绪      | ready / rendering / disconnected / stale / unavailable 与原因；部分成功分项列明，结构读取成功不代表图片成功。                              |

文本结果建议默认限制在 8 KiB 以内，图片独立传输；这是待测的原型预算。完整 objects、完整编译诊断和堆栈只按需读取。不能为了缩短返回，省略项目身份、版本、失败总数和重要阻塞。

**一致性规则：**先确定目标页面和文档版本，再让页面完成对应渲染、测量和截图，回执同时带这些身份。过程中发生编辑、布局回写或切页时，整份上下文重取或返回 stale；不能把新图与旧树拼接。指定期望版本的验收请求必须匹配；“查看最新状态”可以采用完整的新版本，并明确标出版本变化。第一期只做 2D UI，无法可靠测量的节点返回原因，不能用本地 width/height 假充世界包围盒。

### 3.4 Claude 与 Codex 的一致体验

两者使用相同的项目工具、结果结构和保护规则，由用户选择熟悉的 Agent。第一期不强制双 Agent 协作，也不固定“Claude 做美术、Codex 写代码”的角色。

MCP 返回图片后，还要验收客户端确实把图片交给模型。CLI 路径只有文件名不等于模型已看图；适配器需使用客户端支持的图片输入机制。若当前客户端/模型无法读图，应明确“只能结构检查”，不能报告视觉自检完成。

一个任务只有一个 AI 写入者。换 Agent 时交接需求、参考图、目标文档、最后版本、变更及证据路径，并重新读现场；不要求共享模型内部推理。人仍可手动编辑，版本检查负责拒绝过期 AI 操作。

## 4. 修改节点、引用与 Prefab 的边界

### 复用 cocos-cli 的方式

cocos-cli 已有 headless 文档、节点、组件、Prefab、DSL 和 wiring 能力。复用其语义、类型解析和序列化经验，按需转成共享文档服务的操作；不先重写整套 CLI，也不让离线文件写入和当前编辑器争抢同一个文件。旧 Creator IPC 仍存在于代码中，但不作为本产品新增能力的依赖。

第一期现有对象下标可以作为**当前实例 + docId + epoch/version 范围内的短期句柄**。服务端版本检查必须先于索引解析，结构修改后重新读取句柄。稳定跨版本 ID 留到需要时再做，不能让 AI 把序列化数组下标长期记为节点身份。

| 用户要求              | 实际要处理的语义                                 | 最小检查                                                                 |
| --------------------- | ------------------------------------------------ | ------------------------------------------------------------------------ |
| 调整布局/样式         | 节点变换、Label/Sprite、Widget/Layout 等组件属性 | 属性类型、组件限制、实际渲染尺寸；区分布局驱动值与可直接修改值。         |
| 把字段指向某节点      | `Node` 引用                                      | 目标属于允许的文档范围；同名节点先消歧。                                 |
| 把标题/图标绑定到脚本 | `Label`、`Sprite` 或自定义组件引用               | 解析真实脚本 UUID 和字段类型；绑定组件本身，不能把其所在 Node 当成组件。 |
| 更换图片/字体         | 资源 UUID 与子资源类型                           | 校验 `.meta` 和 SpriteFrame/Texture 等区别；保留资源身份。               |
| 修改数组/对象字段     | 有序的引用数组和可序列化 ccclass 对象            | 明确 replace/append/remove 语义，避免每次重试都重复追加。                |
| 绑定按钮事件          | target、component、handler、custom data          | 保留无关事件；检查 handler 存在、目标组件匹配；随后回读事件表。          |
| 删除或复制子树        | 内外引用与 Prefab 来源关系                       | 删除先列引用影响；复制重映射内部引用，外部引用明确保留/清空。            |

例如示例 Prefab 的显示字段 `Room Name` 指向 `game_name` 上的自定义 `AutoResizeLabel`，不能仅因为名字含 Label 就替换成 `cc.Label`。具体序列化字段名与类型必须读 schema/脚本确认。`Fee Num → coin_txt`、`onClickTuple` 等也要以现场回读为准，不凭截图文字直接写值。

**保留 `SYNCED_PREFAB` 保护。**现有服务已拒绝 AI 修改自动同步实例中保存后会丢失的内容，也保护指向这类内部对象的引用。遇到它应说明来源 Prefab，并在任务允许范围内打开源文件编辑；涉及公共源 Prefab 的影响范围扩大时先让用户确认。不能为了让操作通过而自动取消同步、unlink 或把批量操作当绕过入口。

### 批次、并发与超时

当前单文档 batch 已有原子性，AI 同步实例检查也会在副本上依次试跑。第一期补的是统一的 `expectedEpoch/expectedVersion` 服务端前提和可读回执，不是重新开发事务引擎。现有 `putValue` 与会重编号的结构操作存在组批限制，适配时保留；跨批次不能宣传成一次原子操作。

版本前提通过后，写入返回新版本、改动摘要和撤销标识。失败不改变该批的文档/历史；人抢先修改则回读、比较，再决定下一批。AI 不自动覆盖人工新增改动。

第一期不要求文档写入持久保存 24 小时幂等结果。保留现有请求 ID 结果去重，适配器确保不同会话的 ID 不碰撞。相同请求可返回已知回执；没有该记录时，旧版本写入应被拒绝。但“版本冲突”无法证明上一次就是自己写成功：超时后需回读当前状态和可用历史，确认结果。不能确认时显示“结果未知”，不得换成新版本号再执行同一批。完整持久幂等机制留给后续导入/构建等长任务。

### 保存、接受与撤销

- 修改默认进入当前共享文档草稿；AI 与人看到同一份内容。每批可按现有历史撤销。没有额外的第二套 AI 草稿模型。
- 用户要求保存时，核对内存版本与磁盘基线哈希，按现有原子文件写入保存并回读。磁盘已变化先处理冲突，不整文件覆盖。
- 保存是保存整份文档，包括已有人工草稿；交付说明本次 AI 改动和原有改动，不能暗示只写入了 AI 那几项。
- 接受是用户认可结果，不等于 Git commit/push。自动验证和预览是否需要落盘要明确：优先用共享工作副本；只能读磁盘的工具须说明所用版本。
- 撤销只在该批仍位于允许撤销的历史头时直接执行；人后续改过时做字段级回退比较，冲突交给用户，不以全量文件恢复抹掉人工修改。崩溃后的草稿恢复能力需要单独验收，不能由内存 undo 推导。

## 5. AI 自检的三种结论

| 检查层     | 证据                                                     | 能说明什么                                                |
| ---------- | -------------------------------------------------------- | --------------------------------------------------------- |
| 结构与绑定 | 文档回读、字段类型、引用解析、事件表、保存后检查         | 目标存在、类型和序列化正确；不能证明业务逻辑被触发。      |
| 编辑态视觉 | 同版本 PNG、布局测量、资源/脚本诊断                      | 当前 Prefab 在指定取景/尺寸下的呈现；业务组件可能未运行。 |
| 游戏行为   | 指定场景/数据状态的真实 Play、输入、运行状态、日志、截图 | 在已执行条件下的实际行为；未覆盖状态仍须标注。            |

UI 交付至少包含前两层。按钮点击后是否打开窗口、数据刷新是否正确，需要第三层；没有运行条件就报告“绑定检查完成，业务行为未验证”。已有业务错误与本轮新增错误分别列出，相关阻塞仍影响最终结论。

后续业务闭环先选一个可复现页面，固定入口、尺寸、语言和测试数据，再验证普通/选中/禁用、长文本等必要状态。预览不应依赖 AI 随机操作到某个界面。测试数据和临时运行属性不自动写入生产 Prefab。

交付结果保持简短：目标和源版本、改了什么、前后图、关键测量及绑定、已通过/未验证/阻塞项、保存状态。证据与最终修改版本一致；保存或再次修改使旧证据过期时必须标明。完整日志可展开读取。

## 6. 布局、Play 和多项目的产品顺序

### 继续沿用现有工作台

中央保留 Cocos Web；右侧保留“终端”，可选 Claude、Codex 和普通 Shell；原有资源管理器、智能体历史、源代码控制等入口不删除。

第一期只需在会话启动时提示“已连接：项目 / 当前编辑器”，失败时给修复入口。任务进度、图和结论优先通过现有终端/图片查看能力展示。无需新增复杂聊天面板、任务看板或默认双 Agent 审查。后续可加“把选中节点/报错发送给 AI”的小入口，依然调用同一上下文能力。

### 切换 Prefab 与 Play

当前文件读写/观察通过第一批后，再补 AI 打开并展示指定 Prefab：服务打开文档与页面切换分别有回执。沿用 `editor_open` 作数据入口；页面适配对应长期目录的 `ui.document.show`，不使用未定义的“view attach”。只切换绑定页面，保留其他标签和草稿；用户已离开该页面时提示可查看结果，不抢焦点。

独立浏览器 Play 依照[预览设计](browser-preview-design.md)后置：Orca 内默认新浏览器标签，右侧 AI 会话保持；系统浏览器可选。先补实际运行 ready、日志和源版本回执，再交付“自动点 Play 看结果”。仅获得 URL 或服务端 booting 不算运行成功。当前 Prefab 编辑截图闭环可先完成，不等待 Play 改版。

### 多项目与内存

保留“最多 3 个活跃项目实例”的产品设想作为测量后的试行配置。先记录各项目服务、Chromium/页面、编译进程与缓存的内存，以及冷热恢复时间，再确定默认值。添加项目数量和活跃实例数量分开。

现有 `preview_cache.rs` 的 4 项目 / 默认 768 MiB 是**单进程预览缓存的估算保留预算**；不是 4 个编辑器实例上限，不包含全部浏览器/引擎内存。当前使用的超大项目也可能超过预算。不能拿它与 3 个实例简单相加或互相替代。

后续第一步仅在 Orca 自己管理的实例表中回收闲置、干净、未被任务占用的实例；外部服务不纳入强制回收。人正在编辑、AI 在执行、未保存或预览运行中的实例受保护；没有可回收项就提示容量原因。跨进程计数、租约和持久恢复留到确有需要时做，详见[预算设计](instance-budget-design.md)。

Rust 有利于部分索引、解析和服务工作，但浏览器渲染、脚本编译、资源加载、锁竞争都会造成等待。切分支要合并文件变化、取消过期工作、保留冲突草稿；产品目标是等待可见、可取消、其他项目可用，不能承诺“因为 Rust 所以零卡顿”。

### 当天评审提供的现象

用户转来的 Claude 评审记录：AI open 耗时约 67 秒；AI 服务端口 59124、用户编辑器 56900；MCP 从 3.8.271 变成 3.8.66；一次预览文本约 42 KB、含 428 条编译诊断。这些是该会话的报告值，本次没有重现，也不代表当前正在运行的端口或版本。

源码确认 `editor/project_ops.rs::running_record` 的连接超时为 500 ms、读取超时为 2 秒，读取/解析/项目校验失败会归为未响应并尝试删除运行记录。它构成值得优先验证的重复服务风险；没有证据把当天分流、67 秒或版本漂移全部归因于此。第一批实现时需要记录实际二进制来源、实例身份、复用/新建原因和阶段耗时，分别定位。
