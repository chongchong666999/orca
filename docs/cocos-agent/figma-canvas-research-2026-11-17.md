# Figma 设计稿画布接入 cocos-agent：调研结论

状态：调研结论，2026-11-17，未开始实现。

依据：

- `~/Documents/work/figma-reverse-engineering` 的三轮逆向报告和脚本。
- 本轮对样本 `.fig` 的解码统计，脚本见 [evidence/figma-canvas-2026-11-17](evidence/figma-canvas-2026-11-17/)。
- GitNexus `context-engine`（editor-web、native-engine）和 `cocos-cli` 的源码核对。
- 团队 build-ui 技能，以及 [产品总方案](ai-cocos-product-plan.md)。

## 1. 结论

1. **可以做，做在 Cocos Web 编辑器里。**
   - 解析、渲染和转换放进 GitNexus native-engine，新建 `figma` 模块。
   - 界面放进 editor-web：新增「设计稿」面板，并在 Scene 上叠加设计稿。
   - Agent 通过新的 MCP 工具使用同一套能力。
   - cocos-agent（orca）只升级 a5-game-context 的锁定版本，不新增上游挂点。
2. **它升级的是 M1「参考图 → Prefab」的输入。**
   - 截图只能用来看。`.fig` 带精确的层级、尺寸、文字、字体、9 宫格边距和原图。
   - 切图在本地生成，不需要 `FIGMA_TOKEN`、网络或 API 配额。
   - 现在 build-ui 只能通过 `figma-fetch.mjs` 调 Figma REST 接口。
3. **「算法都有了」需要修正。**
   - 文件格式已经完全打通，本轮已复核。
   - 合成公式大部分已经恢复。
   - 还没有通用渲染器。`render-autobet.cjs` 把坐标和图片 hash 写死，只拼了一张图；阴影用的是 SVG 高斯模糊，不是逆向出来的算法。
   - 样本设计稿中 80% 以上的阴影加在文字上，走通用三角核模糊，而这条路径的半径换算还没有恢复。
   - 通过 §5 的像素门槛之前，不对外宣称达到 Figma 精度。

## 3. 样本设计稿说明了什么

样本是 `figma-reverse-engineering/test-fig`：Poker Master 2 的本地副本，共 49 页。

- **图层名就是转换规则。**
  - `img_` 1,497 个，`txt_` 527 个。
  - `9slice_` 179 个，边距写在名字里，例如 `9slice_popup_button_red_disabled [T30_B30_L30_R30]`。
  - `btn_` 171 个，`tgl_` 41 个，另有 `lbl_`、`mask_`。
  - 因此节点到 Cocos 组件可以按规则转换，不靠模型猜。团队技能目前没有记录这套命名约定。
- **阴影几乎都加在文字上。**
  - 可见投影 759 个，其中 630 个在文字上；内阴影 214 个，其中 167 个在文字上。
  - 文字不是圆角矩形，要走通用三角核路径。所以三角核的半径换算是第一个要补的缺口。
- **字体。**
  - 用到 IBM Plex Sans Condensed、DIN Alternate、Magistral、PingFang SC、方正正黑等。
  - 渲染画面直接用文件里的字形轮廓。
  - 转成 `cc.Label` 时，要映射到项目中有授权的字体；PingFang 只能退回系统字体。
- **自动布局** 共 186 个：横向 135、纵向 39、网格 12。

## 4. 方案（已定）

### 4.1 用户看到什么

1. **设计稿面板**
   - 从 Panel 菜单打开，可以和 Scene 并排。
   - 把 `.fig` 拖进面板即可打开。`.fig` 由 Figma 菜单 File ▸ Save local copy… 保存；zip 包（`canvas.fig` + `images/`）和不含图片目录的 `fig-kiwi` 文件都支持。
   - 面板显示页面、Frame、图层树和画面。点选图层可以看到尺寸、文字、字体、效果和 9 宫格边距。
2. **叠加到 Scene 上**
   - 选中的 Frame 按设计分辨率对齐 Canvas，画在 Scene 的 SVG 层下面。
   - 透明度可调，也可以切换为「差值」模式，直接看出错位。
   - 只用于显示，不写进文档。
3. **生成或更新 Prefab**
   - 按 §4.4 的规则生成节点、切图和组件，作为一次可撤销的批次写进当前文档。
   - 保存仍然走现有的受保护保存。
4. **双向选中**
   - Figma 图层和 Prefab 节点的对应关系存在旁路文件中，点选一边会高亮另一边。
   - 设计稿换版后，按对应关系列出需要更新的内容。
5. **Agent 同样可用**
   - 右侧终端里的 Claude 或 Codex 通过 MCP 读取结构、出图、切图和对比，不需要 `FIGMA_TOKEN`。

### 4.2 放在哪里

- 解析、渲染和转换：GitNexus native-engine 的新模块 `figma`。
- 界面：editor-web 的新面板 `figma`，以及 Scene 的叠加层。默认布局不加这个面板，保持与 Creator 一致。
- orca：只升级 `config/cocos-agent/a5-game-context.lock.json`。

理由：

- Scene 的坐标和相机、文档命令、meta 生成和 MCP 都在这个服务里。
- 放进 orca 要多一层 IPC，还要新增上游挂点，违背 [COCOS-AGENT.md](../../COCOS-AGENT.md) 的低冲突原则。
- 服务在项目所在的机器上运行，面板只从服务取图。因此 CLI、MCP、CI 和远程主机都可以直接使用。
- 新依赖都是纯 Rust，mac、Windows、Linux 一致。

### 4.3 渲染器

做法：

- 用 Rust 在 CPU 上渲染。tiny-skia 负责路径、渐变、图片、遮罩、裁剪和混合。
- 阴影和模糊按逆向出的公式自己实现，包括解析圆角路径和可分离的三角核模糊。
- 服务按 Frame 和缩放倍率输出 PNG。前端只显示图片，按节点包围盒做命中测试。
- 缩放时先用 CSS 过渡，停下后重新出图。

理由：

- 输出结果确定，切图和像素对比可以复现。
- 不依赖浏览器或 GPU，沙箱和 CI 都能运行。
- 一份实现同时服务面板、切图和 MCP。

实现要点：

- 新依赖为 `tiny-skia` 和 `ruzstd`。`flate2`、`image`（png）和 `sha1` 已经在依赖中。
- 实例的渲染顺序：取组件子树，套用 `symbolOverrides`，再套用 `derivedSymbolData`。
- 只按公式重写，不搬运 Figma 的着色器源码或 WASM 代码。

### 4.4 转换为 Prefab 的默认规则

| Figma                                                  | Cocos                                                                                                                                              |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| FRAME、GROUP、没有前缀的 INSTANCE                      | `cc.Node`。尺寸取 Figma 的逻辑包围盒；坐标为 `x = cx − W/2`、`y = H/2 − cy`，与现有 figma-raw 管线一致                                             |
| `txt_` / `lbl_` 文字，且效果能用 Cocos 表达            | `cc.Label`，带上字号、行高、颜色、对齐、溢出方式和字体映射。单个投影用 `cc.LabelShadow`（2.4.13 有 color、offset、blur），描边用 `cc.LabelOutline` |
| 带内阴影、渐变或多重效果的文字（如 AUTOBET、按钮文字） | 烘焙成 PNG，用 `cc.Sprite` 显示                                                                                                                    |
| `img_`                                                 | 整个子树渲染成一张 PNG，用 `cc.Sprite` 的 CUSTOM 尺寸模式；不逐个导出子向量                                                                        |
| `9slice_… [T_B_L_R]`                                   | 9 张源图按原始像素拼成一张贴图，边距写进 meta，Sprite 类型设为 SLICED。名字中的边距与源图尺寸冲突时，以名字为准并给出警告                          |
| `btn_` / `tgl_` / `mask_` 与 Figma 遮罩                | `cc.Button`（复用项目的按钮模板）/ `cc.Toggle` / `cc.Mask`                                                                                         |
| 自动布局 / 约束                                        | `cc.Layout` / `cc.Widget`，`cc.Widget` 只加给需要适配的节点                                                                                        |

补充规则：

- **有阴影外溢的切图**：PNG 按实际渲染范围导出，Sprite 子节点也按渲染范围摆放；外层节点保留逻辑包围盒。这样布局尺寸与 Figma 一致，像素也不会被压缩。
- **去重**：同一组件的多个实例只切一张图，按渲染结果的哈希去重；重复出现的项做成模板，配合 `cc.Layout`。
- **复用项目原图**：
  - 先按 SHA-1 在项目 assets 中找原图。设计师直接拖进 Figma 的项目原图，hash 会与项目文件一致，可以直接复用已有的 sprite-frame。
  - 找不到原图时，再按像素哈希找相同的图。
  - 新切图写到新路径，不覆盖已有图片。
- **新增服务命令 `insertNodes`**：
  - 现有 `editor_apply` 不能新建节点，所以新增这个命令。它接收 Creator 2.4 序列化格式的子树，做法沿用 `instantiatePrefab` 接收序列化对象数组的方式。
  - 面板和 MCP 共用这个命令，一次批次即一步撤销。

## 8. 原型与实测（2026-11-17 晚）

原型在 [prototypes/fig-viewer](prototypes/fig-viewer/)：`fig-viewer.html` 是单文件网页，用浏览器打开后选择 `.fig` 即可，文件只在本机读取；`build.mjs` 把 `src/` 里的脚本合成这个文件。

用的是 `Poker Master 2 - Partial file saved 2026-11-17.fig`（212 MB，29.4 万个图层），在 Node 里实测：

| 项目                      | 结果                                                                                                                                                     |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 打开文件                  | 1.3 秒：读取 22 ms，zstd 解压 585 ms（内置 fzstd，MIT），建目录 703 ms；内存约 390 MB                                                                    |
| 渲染 `popup_autobet_base` | 1920 × 1080 约 0.8 秒，展开 20 个组件实例                                                                                                                |
| 稳定性                    | 84 个 frame 无报错；暂不支持的只有视频填充和图片调色                                                                                                     |
| 与原生导出逐像素对比      | 6 个元素里，差值 ≤ 2 的像素占 76%–93%；差异集中在 1 像素宽的边缘（路径和文字的抗锯齿）和缩小的图片（标题图 54%–59%）。抗锯齿和图片采样补上后的结果见 8.1 |

逆向补上的结论：

- **模糊核**：f3281 只在兜底路径调用 f25196 / f25198；f17769 算出 `count = min(0.5 × 模糊值 × 缩放 / 降采样比, 64)`，扩边为 `0.5 × 模糊值 + clamp(模糊值, 1, 6)`。用原生导出里的文字投影校准，核宽系数在 1.0 附近最好（提示语 88.3% → 92.8%）。结论：每个方向用三角核，半宽 = 面板模糊值 × 缩放；渲染树里存的模糊值是面板值的 2 倍。
- **图层顺序**：同级图层按文件里的顺序从后往前画；tooltip 盖住提示语，与原生导出一致。Dev Mode 的图层列表也是这个顺序。
- **九宫格接缝**：Figma 原生导出里同样有；接缝深浅由图片上边界的取舍规则决定，见 8.1。

这台机器上 REA 的 `decompile` 依赖 Ghidra，而 Ghidra 没有配置，所以本轮改用 WABT 加原有脚本读字节码。

### 8.1 抗锯齿与图片采样（2026-11-18）

基准是 11-18 在 Figma 里导出的 `Design Preview - Rankings@1x.png`（3200 × 1700），和这份文件的同一个节点逐像素比较。弹窗区域（1440 × 1060）的结果：

| 渲染方式                                 | 差值 ≤ 2 | 差值 ≤ 5 | 平均误差 |
| ---------------------------------------- | -------- | -------- | -------- |
| 原型初版（浏览器自带的抗锯齿和图片采样） | 97.21%   | 97.92%   | 0.419    |
| 按下面的规则                             | 99.83%   | 99.96%   | 0.119    |

文字区域的失配像素从 4308 个降到 3 个。规则来自 `compiled.wasm` 里的着色器，参数用原生导出拟合：

- **路径**：用「模板 + 覆盖」画进 4 倍多重采样目标。着色器里没有解析式抗锯齿：模板阶段只有曲线的 discard，覆盖阶段只输出 `color * alpha`。导出图的文字边缘只有 3 个中间灰阶，对应每像素 4 个采样点。采样点是标准 4x 位置 (0.375, 0.125)、(0.875, 0.375)、(0.125, 0.625)、(0.625, 0.875)。
- **顶点**：吸附到 1/256 像素；落在边上的采样点按左上规则归属。
- **曲线**：先展平，逐次二分，直到每段控制多边形的二阶差分 ≤ 1 像素，也就是弦误差 ≤ 1/4 像素；三次曲线按 Wang 公式多乘 3/4。按像素中心判定的 Loop-Blinn 方式实测更差，WGSL 后端里也没有曲线 discard 着色器。
- **帧裁剪**：在同一组采样点上求交，等同于模板裁剪；图层合成时再乘上裁剪覆盖率。不能用画布自带的 clip，否则边缘会被抗锯齿两次。
- **图片**：先建金字塔，每级用双线性缩到 ceil(w/2) × ceil(h/2)，选「仍不小于绘制尺寸」的最小一级，在像素中心做双线性采样（夹边，按预乘处理）。奖杯图把 160 × 153 画成 80 × 76.5，逐行拟合出的权重和这个模型一致，该区域 100% 的像素差值 ≤ 2。
- **图片边界**：像素中心正好落在图片上边界时算作图片外，落在下边界时算作图片内。弹窗顶边和两条九宫格缝只有这样才对得上。
- **缺图**：Figma 画 `rgba(158,170,186,0.12)`，和原型的占位色相同；占位也按 4 采样覆盖率画。
- **双三次（可选）**：导出设置 `useBicubicSampler` 对应的重采样着色器已复现。它用 Keys 三次核，c = −clamp(输入高 / 输出高, 1, 2.5)；缩小时核宽随比例放大，每边最多 12 个采样。这次导出用它反而更差（97.85%），11-12 的 autobet 截图用它更好（标题 57% → 69%）。什么条件下走双三次还没定位到：调用点 f39880 的开关来自闭包捕获，只追到 variant 分派表。

还没解决：

- 非整数缩放的小图标（硬币、排序图标、关闭按钮）还差 1–3 个色阶。
- 渲染变慢：Rankings 整帧从 0.54 秒变成 1.9 秒；Popups 页 86 个 frame 共 45 秒，无报错。
- 把设计稿转成渲染树的代码仍未定位，效果先后顺序要在那里确认。
